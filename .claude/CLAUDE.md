# @madebyjulz/schwifty-ts

A 1:1 TypeScript port of the Python `schwifty` package (vendored as the `schwifty-py` submodule).
Read `README.md` for the API and the porting workflow.

## Porting rules

- The Python source is the source of truth. Files, classes, methods and private helpers mirror
  their Python counterparts one-to-one (`snake_case` becomes `camelCase`; `_private` stays
  `_private`). Do not refactor the TypeScript side away from the Python structure, even where it
  repeats itself (e.g. the German checksum classes), because diffability against upstream matters
  more than brevity.
- Deviate only where JavaScript requires it (no `str` subclassing, no lazy file loading, `bigint`
  cost). Comment the deviation where it happens and list it in `CHANGELOG.md`.
- Tests in `tests/` mirror `schwifty-py/tests/`. Port new upstream tests together with the code.
- Port upstream releases with `/port-upstream` (`.claude/skills/port-upstream/`). Use
  `pnpm sync:upstream` to update the submodule and see what changed, `pnpm parity` to compare the
  build with Python, and `pnpm sync:upstream --record` to record the ported revision
  (`schwifty.upstream` in `package.json`). A port is several commits and one release: the last
  commit carries the changelog entry, the version and the recorded revision.
- `src/data/` is generated by `scripts/consolidate-registry.ts` from the submodule. Never edit it
  by hand; CI fails when it is stale.

## Versioning

Release-month CalVer of this package (`2026.9.0`, `2026.9.1`, ...), independent of the upstream
version. Record the ported upstream revision in `package.json` (`schwifty.upstream`) and name it
in the changelog entry. See `README.md`.

## Git hygiene

Stage files explicitly (`git add <paths>`), never `git add -A`. Tooling occasionally drops files
such as `.env` into the tree.

## Tooling

This project uses **pnpm** (never npm or yarn; the version is pinned via `packageManager`) and
**Ultracite** on top of **oxlint** and **oxfmt** (not Biome).

- Format: `pnpm fix`
- Lint and format check: `pnpm check`
- Typecheck: `pnpm typecheck`
- Tests: `pnpm test` (vitest)
- Parity with Python: `pnpm parity` (needs `uv`; tests `dist`, which `pnpm test` does not; runs
  automatically before publishing)
- Build: `pnpm build` (tsdown; `prebuild` regenerates `src/data` when the submodule is checked out)

Run `pnpm fix && pnpm check && pnpm typecheck && pnpm test` before committing.

## Code standards

- Strict TypeScript, `erasableSyntaxOnly` (const objects instead of enums), no `any`; prefer type
  narrowing over assertions and mark the unavoidable ones with an `oxlint-disable-next-line`
  comment that explains why.
- Named constants instead of magic numbers, `for...of` over `.forEach()`, early returns over
  nesting, template literals over concatenation.
- Throw `Error` subclasses from `src/exceptions.ts` with descriptive messages.
- No `console.log` outside `scripts/`.
